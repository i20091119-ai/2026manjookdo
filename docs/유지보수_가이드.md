## 1. 전체 구조 이해하기

### Apps Script를 더 이상 쓰지 않습니다

예전에는 구글 Apps Script에 코드를 붙여넣고 "배포 → 배포 관리 → 새 버전"을
눌러야 반영됐습니다. 지금은 **GitHub에 저장하면 끝**입니다.

### 동작 흐름

```
구글 설문 응답 시트 4개
   ↓   GitHub Actions 가 자동으로 읽어옴
        (매시 정각 + 필요할 때 수동)
site/data.json   ← 통계에 필요한 값만 뽑아 담은 파일
   ↓   GitHub Pages 가 웹사이트로 띄움
site/index.html  ← 브라우저가 data.json을 받아 표를 계산해서 그림
```

**핵심 1**: 서버가 없습니다. 그냥 파일 두 개(HTML + JSON)를 웹에 올려 둔 겁니다.

**핵심 2**: **화면은 실시간이 아닙니다.**
설문 응답이 들어와도 위 시각에 갱신이 돌기 전까지는 화면에 안 나옵니다.
바로 보고 싶으면 **Actions 탭에서 수동 실행**하면 2~3분 뒤 반영됩니다.
화면 오른쪽 위 "갱신 ○○" 표시가 마지막으로 시트를 읽어 온 시각입니다.

## 2. 처음 세팅 (한 번만)

GitHub이 내 구글 시트를 읽을 수 있게 **열쇠**를 만들어 주는 작업입니다.
한 번만 하면 그다음부터는 신경 쓸 일이 없습니다. **20~30분** 정도 걸립니다.

전체 흐름:

```
① 구글에 "프로그램용 계정"을 만들고 열쇠 파일을 받는다   (10분)
② 시트 4개를 그 계정에 보여준다                        (5분)
③ 열쇠와 비밀번호를 GitHub에 맡긴다                     (3분)
④ GitHub Pages를 켠다                                  (1분)
⑤ 실행한다                                             (3분)
```

---

### ① 구글 서비스 계정 만들고 열쇠 받기

**"서비스 계정"이 뭔가요?**
사람 대신 **프로그램이 쓰는 구글 계정**입니다. 이메일 주소처럼 생겼지만
사람이 로그인할 수는 없고, 프로그램이 "이 계정입니다" 하고 증명하는 데만 씁니다.
GitHub이 내 개인 구글 계정 비밀번호를 알 필요가 없어지는 게 핵심입니다.

> 💰 **돈 안 듭니다.** 구글 클라우드 콘솔에 들어가지만
> 시트 읽기는 무료 범위 안이고, 결제 정보를 등록할 필요도 없습니다.
> 혹시 "결제 계정을 만드세요" 창이 뜨면 **닫으셔도 됩니다.**

#### 1-1. 구글 클라우드 콘솔 접속

https://console.cloud.google.com 에 접속합니다.
(대시보드 시트를 갖고 있는 구글 계정으로 로그인하세요)

처음 들어가면 **약관 동의** 화면이 나옵니다. 국가 선택하고 체크 후 **동의**.

#### 1-2. 프로젝트 만들기

1. 화면 **맨 위 왼쪽**, 구글 클라우드 로고 옆에 프로젝트 선택 칸이 있습니다
   (`프로젝트 선택` 또는 `My First Project` 라고 쓰여 있음) → 클릭
2. 팝업 오른쪽 위 **새 프로젝트** 클릭
3. 프로젝트 이름: `수학문화관대시보드` (아무거나 상관없음)
4. **만들기** 클릭 → 30초쯤 기다립니다

> ⚠️ **여기가 초보자가 가장 많이 놓치는 곳입니다.**
> 만들기가 끝나면 알림이 뜨는데, **그 알림의 '프로젝트 선택' 을 눌러야**
> 방금 만든 프로젝트로 들어갑니다.
> 화면 맨 위에 `수학문화관대시보드` 라고 떠 있는지 꼭 확인하세요.
> 다른 프로젝트가 선택된 상태로 진행하면 나중에 안 됩니다.

#### 1-3. Google Sheets API 켜기

기본 상태로는 구글이 "시트를 읽어도 된다"고 허락하지 않습니다. 켜 줘야 합니다.

1. 화면 **맨 위 검색창**에 `Google Sheets API` 입력
2. 결과에서 **Google Sheets API** 클릭
3. 파란 **사용** 버튼 클릭 (이미 켜져 있으면 '관리'라고 나옵니다 — 그냥 넘어가세요)

#### 1-4. 서비스 계정 만들기

1. 왼쪽 위 **☰(햄버거) 메뉴** → **API 및 서비스** → **사용자 인증 정보**
2. 화면 위쪽 **+ 사용자 인증 정보 만들기** → **서비스 계정** 선택
3. **서비스 계정 이름**: `dashboard-reader` (아무거나)
   - 그 아래 **서비스 계정 ID**가 자동으로 채워집니다. 그대로 두세요.
4. **만들고 계속하기** 클릭
5. **"이 서비스 계정에 프로젝트에 대한 액세스 권한 부여"** — **아무것도 선택하지 말고** **계속** 클릭
   (역할을 줄 필요가 없습니다. 시트 권한은 다음 단계에서 시트 쪽에서 줍니다)
6. **"사용자에게 이 서비스 계정에 대한 액세스 권한 부여"** — 비워 둔 채 **완료** 클릭

> ❓ **"OAuth 동의 화면을 구성해야 합니다" 라는 노란 배너가 떠요**
>
> **무시하세요. 건드릴 필요 없습니다.**
> OAuth 동의 화면은 *사람이 로그인해서 "이 앱에 권한을 줄까요?" 하고 승인할 때*만
> 필요합니다(화면 위쪽 `OAuth 2.0 클라이언트 ID` 쪽 이야기).
> 서비스 계정은 사람의 승인 없이 **열쇠 파일로 직접 증명**하는 방식이라
> 동의 화면이 끼어들 자리가 없습니다. 저 배너는 이 페이지에 늘 떠 있는 안내입니다.

#### 1-5. 열쇠(JSON 파일) 받기

1. 목록에 방금 만든 서비스 계정이 보입니다 → **이메일 주소를 클릭**
2. 상단 탭 중 **키** 클릭
3. **키 추가** → **새 키 만들기**
4. 키 유형 **JSON** 선택 (기본값) → **만들기**
5. **JSON 파일이 자동으로 다운로드됩니다.**
   이름은 `수학문화관대시보드-a1b2c3d4e5f6.json` 같은 모양입니다.

> 🔑 **이 파일이 열쇠입니다.**
> - 다시 받을 수 없습니다 (잃어버리면 4~5번을 다시 해서 새로 만들면 됩니다)
> - **아무한테도 보내지 마세요.** 비밀번호와 같습니다
> - 카카오톡·메일로 자기한테 보내는 것도 하지 마세요

#### 1-6. 계정 이메일 주소 메모

같은 화면 위쪽에 **이메일** 항목이 있습니다.

```
dashboard-reader@수학문화관대시보드-123456.iam.gserviceaccount.com
```

이런 모양의 긴 주소입니다. **복사해서 메모장에 붙여넣어 두세요.**
다음 ② 단계에서 시트 4개에 각각 붙여넣습니다.

이게 "이 프로그램이 시트를 읽습니다" 하고 구글에 알려 주는 이름표입니다.

> 다운로드한 JSON 파일을 메모장으로 열어도 `"client_email"` 항목에 같은 주소가 있습니다.

### ② 시트 4개를 그 계정에 공유하기

방금 만든 서비스 계정에게 "이 시트들 봐도 된다"고 허락해 주는 단계입니다.

**먼저 서비스 계정 주소를 준비하세요.** ①에서 만든 그 주소입니다.

```
dashboard-reader@mathnumber.iam.gserviceaccount.com
```

> ⚠️ **본인 지메일 주소가 아닙니다.** `…iam.gserviceaccount.com` 으로 끝나는
> "프로그램용 계정" 주소입니다.
>
> 기억이 안 나면 **API 및 서비스 → 사용자 인증 정보** 화면 맨 아래
> **서비스 계정** 목록에 파란 글씨로 있습니다.
> 또는 다운로드한 JSON 파일을 메모장으로 열어 `"client_email"` 항목을 보세요.

아래 4개 링크를 하나씩 열고, **똑같은 작업을 4번** 반복합니다.

| 설문 | 링크 |
|---|---|
| 자유관람 | https://docs.google.com/spreadsheets/d/1yZfJfJdEMJGZu9TMDXXDDk0edqURtIEUiwGlDRNRpag/edit |
| 교구대여 | https://docs.google.com/spreadsheets/d/1_QHrQqTM4_J9rA4iw7dudEHqy2vhEzyXR7I9xrQW1Vs/edit |
| 학교·가족 프로그램 | https://docs.google.com/spreadsheets/d/1TzfWGDGqqbYxpsqgXXPT7dtWGYy7hbKBrkctFk-CO3g/edit |
| 여름방학 캠프 | https://docs.google.com/spreadsheets/d/1csbLxMowWSNJ0LGFnrYa-Z6cC5ICJ_3FOe4UMhWqTts/edit |

**각 시트에서:**

1. 오른쪽 위 **공유** 버튼 클릭
2. **"사용자 및 그룹 추가"** 칸에 위 서비스 계정 주소를 **붙여넣기** → Enter
3. 권한을 **뷰어**로 선택 ⚠️ (편집자로 주지 마세요. 읽기만 하면 됩니다)
4. **"알림 이메일 보내기"** 체크를 **해제** (서비스 계정은 메일함이 없습니다)
5. **공유** 클릭

> 💡 **주소를 입력해도 자동완성이 안 뜹니다.** 정상입니다.
> 그냥 전체를 붙여넣고 Enter를 누르면 칩(chip) 모양으로 들어갑니다.
>
> "이 사용자는 Google 계정이 없습니다" 같은 안내가 나와도 그대로 진행하세요.

> ⚠️ **4개 전부 해야 합니다.** 하나라도 빠뜨리면 그 설문만 통계가 비어 나옵니다.
> 나중에 Actions 로그에 `403 permission` 이라고 뜨면 이 단계를 빠뜨린 겁니다.

### ③ 열쇠와 비밀번호를 GitHub에 맡기기

1. 이 주소로 들어갑니다:
   **https://github.com/i20091119-ai/2026manjookdo/settings/secrets/actions**
   (또는 저장소 → **Settings** → 왼쪽 **Secrets and variables** → **Actions**)
2. 초록색 **New repository secret** 클릭
3. **Name** 칸에 정확히 입력:

   ```
   GOOGLE_SERVICE_ACCOUNT_JSON
   ```

   ⚠️ 오타가 있으면 동작하지 않습니다. 위 줄을 복사해 붙여넣으세요.

4. **Secret** 칸에 **JSON 파일 내용 전체**를 붙여넣습니다.
   - ①-5에서 받은 JSON 파일을 **메모장**으로 엽니다
     (파일 우클릭 → 연결 프로그램 → 메모장)
   - `Ctrl+A` (전체 선택) → `Ctrl+C` (복사)
   - Secret 칸에 `Ctrl+V`

   > ⚠️ 맨 앞의 `{` 와 맨 뒤의 `}` 까지 **전부** 들어가야 합니다.
   > 일부만 복사하면 `구글 토큰 발급 실패` 오류가 납니다.
   > 붙여넣은 뒤 맨 아래로 스크롤해서 `}` 로 끝나는지 확인하세요.

5. **Add secret** 클릭

#### 비밀번호도 등록합니다

같은 화면에서 **New repository secret** 을 **한 번 더** 누릅니다.

| 칸 | 값 |
|---|---|
| **Name** | `DASHBOARD_PASSWORD` |
| **Secret** | `3141` |

**Add secret** 클릭.

> 이 비밀번호로 `data.json` 을 **암호화**합니다.
> 비밀번호를 모르면 파일을 받아도 의미 없는 바이트 덩어리만 나옵니다.
> 비밀번호가 코드에 남지 않도록 여기(Secret)에만 둡니다.

등록되면 목록에 두 개가 보입니다.

```
DASHBOARD_PASSWORD
GOOGLE_SERVICE_ACCOUNT_JSON
```

**값은 다시 볼 수 없습니다** (GitHub도 안 보여줍니다). 정상입니다.

### ⑤ 실행하기

1. 이 주소로 들어갑니다:
   **https://github.com/i20091119-ai/2026manjookdo/actions**
   (또는 저장소 위쪽 **Actions** 탭)
2. 왼쪽 목록에서 **데이터 갱신 & 배포** 클릭
3. 오른쪽에 **"This workflow has a workflow_dispatch event trigger."** 라는 안내와

## 4. 월말 집계 탭

### 무엇을 하는 탭인가

선택한 연도·월의 보고서용 표 4개를 자동으로 만들어 줍니다.
각 표 우측의 **📋 복사** 버튼을 누르면 데이터가 클립보드에 복사되고,
한컴/엑셀 양식의 **첫 번째 데이터 셀**에 `Ctrl+V` 하면 그대로 들어갑니다.

> 복사되는 것은 **머리글과 합계 줄을 뺀 데이터 행만**입니다.
> 양식에 이미 머리글과 합계 수식이 있는 것을 전제로 합니다.

| 표 | 내용 | 사람 분류 |
|---|---|---|
| 1. 운영 현황 | 총괄 집계 양식 | 7분류: 유 / 초 / 중 / 고 / 교원 / 보호자 / 일반 |
| 2. 참여자 현황 | 거제 양식 | 6분류: 유아·일반을 '그 외'로 통합 |
| 3. 만족도 통계 | 문항1~5 × 5단계 | — |
| 4. 만족도 결과 | 만족도(%) | — |

**만족도(%) 계산식**

```
만족도(%) = [ '만족' 이상 답변 수의 합 / (설문 응답자 수 × 설문 문항 수) ] × 100
```

- 프로그램 운영 만족도 = 문항1~4 (문항 수 4)
- 강사 만족도 = 문항5 (문항 수 1)

### 프로그램 행을 고치려면

`index.html`의 **`REPORT_PROGRAMS`** 배열 하나만 고치면 4개 표에 모두 반영됩니다.
(904번째 줄 근처)

```javascript
{ grp:0, no:'1-(08)', name:'가족과 함께하는 수학체험교실',
  src:'prog',           // 어느 시트: 'free' | 'educ' | 'prog' | 'camp' | null
  field:'programType',  // 무엇으로 거를지
  filter:'가족수학체험프로그램',   // 시트 B열 값과 정확히 일치해야 함
  hasInstructor:true }, // 문항5(강사 만족도)가 있는 설문인지
```

- **`src:null`** 로 두면 데이터 원천이 없는 행이 되어 **회색 양식으로만** 표시됩니다.
  (경남학생수학탐구페스티벌, 기타, 직무연수가 여기에 해당)
- **`filter`에 배열**을 주면 여러 설문 종류를 한 행으로 합산합니다.

### 캠프가 어떻게 집계되는가

캠프 설문에는 응답자 구분 컬럼이 없습니다.
그래서 **캠프 종류명에 들어 있는 학교급**으로 분류합니다.

| 캠프 종류 | 분류 | 들어가는 행 |
|---|---|---|
| 초등학생 체험수학캠프 | 초 | 1-(03) 학생체험수학캠프 |
| 중학생 체험수학캠프 | 중 | 1-(03) 학생체험수학캠프 |
| 고등학생 인공지능수학캠프 | 고 | 1-(03) 학생체험수학캠프 |
| 초등학생 SW캠프 | 초 | 1-(04) 학생SW체험캠프 |

캠프 종류가 새로 생기면 두 곳을 함께 고칩니다.

1. `TABS` 배열 — 상세 탭을 추가하려면
2. `REPORT_PROGRAMS`의 `1-(03)` 또는 `1-(04)` 행 `filter` 배열 — 월말 집계에 넣으려면

> 종류명에 '초등/중학/고등'이 없으면 '일반'으로 분류됩니다.
> 종류명 규칙이 바뀌면 `schoolLevelOfCamp()` 함수를 고쳐야 합니다.

### 사람 분류 규칙

`classifyPerson()` 함수가 응답자 텍스트를 7분류로 바꿉니다.
**위에서부터 순서대로 검사**하므로 순서가 중요합니다.

```javascript
'유아' 포함                  → 유         ← 반드시 맨 위 (2026-09~)
'학부모' 또는 '보호자' 포함  → 보호자
'교원'/'교사'/'교직원' 포함  → 교원
'초등' 포함                  → 초
'중학' 포함                  → 중
'고등' 포함                  → 고
'학생' 포함 (구버전 단독 표기) → 초
그 외                        → 일반
```

`'초등학생 학부모'`가 `'보호자'`로 가는 이유가 이 순서 때문입니다.
학부모 검사를 '유아' 검사보다 위로 올리면 학부모가 학생으로 집계되는 버그가 생깁니다.

> ⚠️ **'유아'만 예외로 맨 위에 있습니다.** 유아는 설문을 스스로 못 써서
> 응답이 항상 `'유아 학부모'`로만 들어옵니다. 다른 `'OO 학부모'`처럼 보호자로 세면
> 자유관람의 유아 헤드카운트가 월말 집계에서 영원히 0으로 나옵니다
> (실제로 이 버그가 있었고, 2026-09에 발견해 고쳤습니다).
> 초등학생 학부모/중학생 학부모/고등학생 학부모는 지금도 그대로 보호자로 셉니다 —
> 유아만의 예외입니다.

### 5-1. 비밀번호를 바꾸고 싶을 때

**저장소 Settings → Secrets and variables → Actions** 에서
`DASHBOARD_PASSWORD` 옆 연필 아이콘을 눌러 새 값을 넣고 **Update secret**.

새 비밀번호로 다시 암호화됩니다. **이때부터 예전 비밀번호는 안 통합니다.**

> 자릿수를 4자리가 아닌 것으로 바꾸려면 `site/index.html` 의
> `maxlength="4"` 와 점 4개 표시(`d0`~`d3`)도 함께 고쳐야 합니다.

#### 이 비밀번호가 실제로 무엇을 막나요

`data.json` 은 **통계 내용이 통째로 암호화되어** 있습니다
(AES-256-GCM, 키는 PBKDF2-SHA256 60만 회로 비밀번호에서 만듭니다).
비밀번호 없이 파일을 받으면 의미 없는 바이트 덩어리입니다.
브라우저가 비밀번호로 풀어서 표를 그립니다.

- ✅ URL을 우연히 알게 된 사람 → 아무것도 못 봅니다
- ✅ `data.json` 을 직접 받아 가는 사람 → 암호문만 얻습니다
- ⚠️ **작정하고 덤비는 사람** → 4자리는 경우의 수가 1만 가지라,
  파일을 받아 전부 대입해 보면 뚫립니다

> 🔐 **더 튼튼하게 하려면 비밀번호를 길게 쓰세요.**
> `DASHBOARD_PASSWORD` 를 `gnmc2026math` 처럼 8자 이상으로 바꾸면

```javascript
    }),
  },
```

> 스프레드시트 ID는 URL에서 `/d/` 와 `/edit` 사이의 긴 문자열입니다.
> **새 시트도 서비스 계정에 뷰어로 공유해야 합니다** (2절 ② 참고).

#### ② `site/index.html` 수정

### 5-6. 응답자 분류를 바꾸고 싶을 때

설문 보기 항목이 바뀌면 분류 매핑을 수정해야 합니다.
**세 군데 있으니 목적에 맞는 곳을 고르세요.** 전부 `site/index.html` 입니다.

| 함수/상수 | 줄 번호 | 어디에 쓰이나 |
|---|---|---|
| `FREE_PART_ENTRIES` | 276 | 자유관람 상세 탭 |
| `mapProgRespondent()` | 300 | 학교·가족 상세 탭 |
| `classifyPerson()` | 1016 | **월말 집계 표 1·2** |

#### 자유관람 (상세 탭)

```javascript
const FREE_PART_ENTRIES = [
  ['유아 학부모',    '유아'],              // ← 유아만 예외 (아래 설명 참고), 맨 위
  ['학부모 등 보호자','학부모 등 보호자'],
  ['초등학생 학부모','학부모 등 보호자'],
  ...
];
```

- 앞의 값 = 시트에 실제로 들어오는 텍스트
- 뒤의 값 = 통계에 표시할 분류명

> ⚠️ **순서가 중요합니다.** `초등학생 학부모`가 `초등학생`보다 **위에** 있어야 합니다.
> 위에서부터 검사하기 때문에, 짧은 키가 먼저 오면 학부모가 학생으로 집계됩니다.
>
> **`유아 학부모`만 예외로 `'유아'`로 분류합니다** (다른 `'OO 학부모'`는 그대로 `'학부모 등 보호자'`).
> 유아는 설문을 스스로 못 써서 응답이 항상 `유아 학부모` 하나뿐입니다.
> 다른 학부모류처럼 보호자로 세면 자유관람에서 유아 헤드카운트가 절대 안 잡힙니다
> (2026-09에 발견한 버그 — 월말 집계 표1의 '유' 칸이 항상 0으로 나왔습니다).

#### 학교·가족 프로그램 (상세 탭)

⚠️ **'학생'으로 뭉개면 안 됩니다.** 유아/초등학생/중학생/고등학생을 구분해서 반환해야
대상별 카드·표에 학년이 나뉘어 나옵니다. 예전에는 전부 `'학생'` 하나로 합쳐서
학년 구분 없이 나오는 버그가 있었습니다 (2026-09 수정).

```javascript
function mapProgRespondent(v) {
  const s = (v||'').trim();
  if (!s) return null;
  if (s.includes('학부모') || s.includes('보호자')) return '학부모 등 보호자';
  if (s.includes('교원') || s.includes('교사') || s.includes('교직원')) return '교원';
  if (s.includes('유아')) return '유아';
  if (s.includes('초등')) return '초등학생';
  if (s.includes('중학')) return '중학생';
  if (s.includes('고등')) return '고등학생';
  if (s.includes('학생')) return '초등학생'; // 학년 표기 없는 구버전 — classifyPerson()과 동일한 규칙
  return '그외';
}
```

새로운 학년 표현이 생기면(예: `'유치원생'`) 여기에 조건을 추가하고,
`buildProg()`의 `respCats` 배열에도 그 이름을 넣어야 카드·표에 보입니다.

#### 월말 집계 (표 1·2)

`classifyPerson()` — 4번 절의 「사람 분류 규칙」 참고.
새 표현이 들어오면 **여기에도** 조건을 추가해야 보고서 숫자가 맞습니다.

### 5-7. 만족도 응답 표현이 바뀌었을 때

**파일**: `scripts/fetch-sheets.mjs` · **위치**: `scoreToNum()` 함수 (111번째 줄 근처)

현재 인식하는 표현:

| 점수 | 표현 |
|---|---|
| 5 | `매우 만족`, `매우만족`, `매우 그렇다`, `5` |
| 4 | `만족`, `그렇다`, `4` |
| 3 | `보통`, `보통이다`, `3` |
| 2 | `불만족`, `그렇지 않다`, `2` |
| 1 | `매우 불만족`, `매우불만족`, `전혀 그렇지 않다`, `1` |

괄호가 붙은 복합형(`매우 만족(매우 그렇다)`)과
구글 폼 '선형 배율'의 숫자(1~5)도 처리합니다.

새 표현이 생기면 해당 점수 줄에 조건을 추가하세요.

```javascript
if (s.indexOf('아주 좋음') === 0) return 5;   // 예시
```

> ⚠️ **검사 순서를 지키세요.** `'매우 불만족'`을 `'불만족'`보다,
> `'불만족'`을 `'만족'`보다 먼저 검사해야 합니다.
> 순서를 바꾸면 불만족 응답이 만족으로 집계됩니다.

수정 후 확인:

```bash
node test/score.test.js
```

### 가장 먼저 볼 곳 — Actions 로그

저장소 **Actions** 탭 → 마지막 실행 클릭 → **구글 시트 읽기** 단계를 폅니다.

```

  ❌ 여름방학 캠프: 403 The caller does not have permission
```

여기서 대부분 원인이 드러납니다.

---

### 증상: 사이트에 "데이터를 불러오지 못했습니다"

`data.json` 이 아직 안 만들어졌거나 배포가 실패한 겁니다.

1. Actions 탭에서 **데이터 갱신 & 배포** 가 초록 체크인지 확인
2. 빨간 X 면 눌러서 어느 단계에서 멈췄는지 확인
3. 한 번도 안 돌렸다면 **Run workflow** 로 수동 실행

---

### 증상: Actions 로그에 `403 The caller does not have permission`

**시트를 서비스 계정에 공유하지 않은 겁니다.** (2절 ②)

해당 스프레드시트 → 공유 → 서비스 계정 이메일(`…iam.gserviceaccount.com`)을
**뷰어**로 추가하세요.

---

### 증상: Actions 로그에 `구글 토큰 발급 실패`

`GOOGLE_SERVICE_ACCOUNT_JSON` 시크릿이 잘못됐습니다.

- JSON 파일 **내용 전체**를 넣었는지 (앞뒤 중괄호 포함)
- 복사하다 일부가 잘리지 않았는지
- Google Sheets API를 **사용** 으로 켰는지 (2절 ①-3)

시크릿을 다시 등록하고 Run workflow 하세요.

---

### 증상: 특정 탭에만 "해당 월의 응답이 없습니다"

화면이 **그 달 시트에 실제로 들어온 값들을 함께 보여줍니다.**
탭의 `filter` 문자열과 다르면 `TABS` 배열의 `filter` 를 시트 값에 맞추세요.

띄어쓰기 하나만 달라도 안 걸립니다. (`초등학생 SW캠프` vs `초등학생SW캠프`)

---

### 증상: 월말 집계의 특정 행만 비어 있음

| 어떻게 보이나 | 원인 |
|---|---|
| 행 전체가 **회색** | `REPORT_PROGRAMS` 에 `src:null` — 원천이 없는 행 (정상) |
| 숫자가 **0** | 설문은 연결됐는데 그 달 응답이 0건 (정상) |
| 흰 행인데 **빈칸** | `filter` 문자열이 시트 값과 안 맞음 |

---

### 증상: 강사 만족도 칸이 비어 있음

자유관람과 교구대여에는 강사 문항(문항5)이 없습니다. **정상입니다.**
`REPORT_PROGRAMS` 의 `hasInstructor` 로 결정됩니다.

---

### 증상: 숫자가 전부 0으로 나옴

**원인 1**: 컬럼 번호가 틀림 → `SOURCES` 의 `toScores(row, 시작열, 개수)` 확인 (5-3)

**원인 2**: 만족도 표현을 인식 못 함 → `scoreToNum()` 확인 (5-7)

**확인 방법** — 사이트에서 `F12` → Console:

```javascript
DATA.camp.rows.slice(0, 3)
```

`scores` 가 `[null, null, ...]` 이면 표현 인식 실패,
값이 엉뚱한 자리에 있으면 컬럼 번호가 틀린 겁니다.

---

### 증상: 새 응답이 화면에 안 보임

**화면은 실시간이 아닙니다.** 오른쪽 위 "갱신 ○○" 시각을 확인하세요.
그 이후에 들어온 응답은 아직 없습니다.

**Actions → Run workflow** 로 바로 갱신할 수 있습니다 (2~3분 소요).

### 증상: 표가 이상해졌는데 되돌리고 싶음

GitHub 저장소에서 파일 → **History** → 예전 버전 → **Revert** 하거나,
그 버전의 내용을 복사해 덮어쓰면 됩니다.
모든 수정 이력이 남아 있어 언제든 되돌릴 수 있습니다.

- 파일별 이력: 저장소에서 파일 열기 → **History**
- 되돌리기: 원하는 시점 → **Revert** 또는 그 내용 복사해 덮어쓰기

예전 Apps Script 판은 `legacy/apps-script/` 에 그대로 남아 있습니다.
