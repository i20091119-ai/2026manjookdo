## 1. 전체 구조 이해하기

### Apps Script를 더 이상 쓰지 않습니다

예전에는 구글 Apps Script에 코드를 붙여넣고 "배포 → 배포 관리 → 새 버전"을
눌러야 반영됐습니다. 지금은 **GitHub에 저장하면 끝**입니다.

### 동작 흐름

```
구글 설문 응답 시트 4개
   ↓   GitHub Actions 가 자동으로 읽어옴
        (한국시간 09시 / 15시 / 21시 + 필요할 때 수동)
site/data.json   ← 통계에 필요한 값만 뽑아 담은 파일
   ↓   GitHub Pages 가 웹사이트로 띄움
site/index.html  ← 브라우저가 data.json을 받아 표를 계산해서 그림
```

**핵심 1**: 서버가 없습니다. 그냥 파일 두 개(HTML + JSON)를 웹에 올려 둔 겁니다.

**핵심 2**: **화면은 실시간이 아닙니다.**
설문 응답이 들어와도 위 시각에 갱신이 돌기 전까지는 화면에 안 나옵니다.
바로 보고 싶으면 **Actions 탭에서 수동 실행**하면 2~3분 뒤 반영됩니다.
화면 오른쪽 위 "갱신 ○○" 표시가 마지막으로 시트를 읽어 온 시각입니다.

## 2. 처음 세팅 (한 번만)

GitHub이 내 구글 시트를 읽을 수 있게 **열쇠**를 만들어 주는 작업입니다.
한 번만 하면 그다음부터는 신경 쓸 일이 없습니다.

### ① 구글 서비스 계정 만들기

"사람 대신 프로그램이 쓰는 구글 계정"입니다.

1. https://console.cloud.google.com 접속 (구글 계정으로 로그인)
2. 상단 프로젝트 선택 → **새 프로젝트** → 이름 아무거나 (예: `수학문화관대시보드`) → 만들기
3. 검색창에 **Google Sheets API** → **사용** 버튼 클릭
4. 왼쪽 메뉴 **API 및 서비스 → 사용자 인증 정보**
5. **사용자 인증 정보 만들기 → 서비스 계정**
   - 이름 아무거나 (예: `dashboard-reader`) → **만들고 계속하기** → **완료**
6. 만들어진 서비스 계정을 클릭 → **키** 탭 → **키 추가 → 새 키 만들기 → JSON** → 만들기
7. JSON 파일이 자동으로 내려받아집니다. **이게 열쇠입니다.**

> 이 파일에 적힌 `client_email` (…@….iam.gserviceaccount.com) 을 메모해 두세요.
> 다음 단계에서 씁니다.

### ② 시트 4개를 그 계정에 공유

설문 응답 스프레드시트 **4개 각각**에서:

1. 우측 상단 **공유** 클릭
2. ①에서 메모한 `client_email` 주소를 붙여넣기
3. 권한을 **뷰어**로 선택 (편집 권한은 줄 필요 없습니다)
4. "알림 이메일 보내기" 체크 해제 → **공유**

> 4개 다 해야 합니다. 하나라도 빠지면 그 설문만 빈 채로 나옵니다.

### ③ GitHub에 열쇠 등록

1. 저장소 → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret**
3. 이름: `GOOGLE_SERVICE_ACCOUNT_JSON`
4. 값: ①에서 받은 **JSON 파일 내용 전체** (메모장으로 열어 `Ctrl+A` → 복사 → 붙여넣기)
5. **Add secret**

### ④ GitHub Pages 켜기

1. 저장소 → **Settings** → **Pages**
2. **Source** 를 **GitHub Actions** 로 선택

> "Deploy from a branch"가 아니라 **GitHub Actions** 입니다.

### ⑤ 첫 실행

1. 저장소 → **Actions** 탭
2. 왼쪽에서 **데이터 갱신 & 배포** 선택
3. 오른쪽 **Run workflow** → **Run workflow**

2~3분 뒤 초록 체크가 뜨면 성공입니다.
주소는 **Settings → Pages** 위쪽에 나옵니다
(보통 `https://아이디.github.io/2026manjookdo/`).

### ⑥ 확인

- [ ] 사이트가 열리고 표가 그려진다
- [ ] 오른쪽 위에 "갱신 2026.08.05 …" 시각이 보인다
- [ ] **월말 집계** 탭에 `1-(03)` / `1-(04)` 캠프 숫자가 찬다
- [ ] 캠프 탭 4개가 보인다
- [ ] **📋 복사** 버튼이 "✅ 복사됨"으로 바뀐다

### ⑦ (선택) 로고 넣기

`site/logo.png` 로 이미지 파일을 하나 올리면 헤더에 로고가 나옵니다.
없으면 그냥 로고 없이 나옵니다 — 오류가 아닙니다.

예전 드라이브 로고를 그대로 쓰려면 아래 주소에서 받아 이름을 `logo.png`로 바꿉니다.

## 3. 평소 사용법

### 데이터만 새로 받고 싶을 때

**Actions 탭 → 데이터 갱신 & 배포 → Run workflow.**
2~3분 뒤 사이트에 반영됩니다.

가만히 둬도 **한국시간 09시 / 15시 / 21시**에 자동으로 돕니다.

> 화면 오른쪽 위 "갱신 ○○" 이 마지막으로 시트를 읽어 온 시각입니다.
> 이 시각 이후에 들어온 응답은 아직 화면에 없습니다.

### 코드를 고쳤을 때

`site/index.html` 이나 `scripts/fetch-sheets.mjs` 를 고쳐서
**GitHub에 push하면 자동으로 배포**됩니다. 따로 누를 게 없습니다.

GitHub 웹에서 바로 고쳐도 됩니다:
파일 열기 → 연필 아이콘 → 수정 → **Commit changes**.

### 갱신 시각을 바꾸고 싶을 때

`.github/workflows/publish.yml` 의 이 줄입니다.

```yaml
    - cron: '0 0,6,12 * * *'
```

**UTC 기준**이라 한국시간에서 9를 빼서 씁니다.
`0,6,12` → 한국시간 09시, 15시, 21시.
매시간 돌리려면 `'0 * * * *'`.

### 반영이 안 될 때

1. Actions 탭에서 마지막 실행이 **초록 체크**인지 확인
2. 브라우저에서 `Ctrl + Shift + R` (강력 새로고침)

## 4. 월말 집계 탭

### 무엇을 하는 탭인가

선택한 연도·월의 보고서용 표 4개를 자동으로 만들어 줍니다.
각 표 우측의 **📋 복사** 버튼을 누르면 데이터가 클립보드에 복사되고,
한컴/엑셀 양식의 **첫 번째 데이터 셀**에 `Ctrl+V` 하면 그대로 들어갑니다.

> 복사되는 것은 **머리글과 합계 줄을 뺀 데이터 행만**입니다.
> 양식에 이미 머리글과 합계 수식이 있는 것을 전제로 합니다.

| 표 | 내용 | 사람 분류 |
|---|---|---|
| 1. 운영 현황 | 총괄 집계 양식 | 7분류: 유 / 초 / 중 / 고 / 교원 / 보호자 / 일반 |
| 2. 참여자 현황 | 거제 양식 | 6분류: 유아·일반을 '그 외'로 통합 |
| 3. 만족도 통계 | 문항1~5 × 5단계 | — |
| 4. 만족도 결과 | 만족도(%) | — |

**만족도(%) 계산식**

```
만족도(%) = [ '만족' 이상 답변 수의 합 / (설문 응답자 수 × 설문 문항 수) ] × 100
```

- 프로그램 운영 만족도 = 문항1~4 (문항 수 4)
- 강사 만족도 = 문항5 (문항 수 1)

### 프로그램 행을 고치려면

`index.html`의 **`REPORT_PROGRAMS`** 배열 하나만 고치면 4개 표에 모두 반영됩니다.
(904번째 줄 근처)

```javascript
{ grp:0, no:'1-(08)', name:'가족과 함께하는 수학체험교실',
  src:'prog',           // 어느 시트: 'free' | 'educ' | 'prog' | 'camp' | null
  field:'programType',  // 무엇으로 거를지
  filter:'가족수학체험프로그램',   // 시트 B열 값과 정확히 일치해야 함
  hasInstructor:true }, // 문항5(강사 만족도)가 있는 설문인지
```

- **`src:null`** 로 두면 데이터 원천이 없는 행이 되어 **회색 양식으로만** 표시됩니다.
  (경남학생수학탐구페스티벌, 기타, 직무연수가 여기에 해당)
- **`filter`에 배열**을 주면 여러 설문 종류를 한 행으로 합산합니다.

### 캠프가 어떻게 집계되는가

캠프 설문에는 응답자 구분 컬럼이 없습니다.
그래서 **캠프 종류명에 들어 있는 학교급**으로 분류합니다.

| 캠프 종류 | 분류 | 들어가는 행 |
|---|---|---|
| 초등학생 체험수학캠프 | 초 | 1-(03) 학생체험수학캠프 |
| 중학생 체험수학캠프 | 중 | 1-(03) 학생체험수학캠프 |
| 고등학생 인공지능수학캠프 | 고 | 1-(03) 학생체험수학캠프 |
| 초등학생 SW캠프 | 초 | 1-(04) 학생SW체험캠프 |

캠프 종류가 새로 생기면 두 곳을 함께 고칩니다.

1. `TABS` 배열 — 상세 탭을 추가하려면
2. `REPORT_PROGRAMS`의 `1-(03)` 또는 `1-(04)` 행 `filter` 배열 — 월말 집계에 넣으려면

> 종류명에 '초등/중학/고등'이 없으면 '일반'으로 분류됩니다.
> 종류명 규칙이 바뀌면 `schoolLevelOfCamp()` 함수를 고쳐야 합니다.

### 사람 분류 규칙

`classifyPerson()` 함수가 응답자 텍스트를 7분류로 바꿉니다.
**위에서부터 순서대로 검사**하므로 순서가 중요합니다.

```javascript
'학부모' 또는 '보호자' 포함  → 보호자     ← 반드시 맨 위
'교원'/'교사'/'교직원' 포함  → 교원
'유아' 포함                  → 유
'초등' 포함                  → 초
'중학' 포함                  → 중
'고등' 포함                  → 고
'학생' 포함 (구버전 단독 표기) → 초
그 외                        → 일반
```

`'초등학생 학부모'`가 `'보호자'`로 가는 이유가 이 순서 때문입니다.
학부모 검사를 아래로 내리면 학부모가 학생으로 집계되는 버그가 생깁니다.

## 5. 상황별 수정 방법

> 어느 파일을 고치든 **GitHub에 저장(commit)하면 자동으로 배포**됩니다.
> GitHub 웹에서 파일을 열고 연필 아이콘을 눌러 바로 고쳐도 됩니다.

### 5-1. 비밀번호는 어디 갔나요?

**없앴습니다.** GitHub Pages 사이트는 URL을 아는 누구나 열 수 있고,
정적 사이트라 비밀번호를 넣어도 화면 소스에 그대로 보여서 아무 의미가 없습니다.
있는 척하는 게 더 위험해서 뺐습니다.

주소를 대외 문서에 싣지 않는 것으로 관리하시고,
**주관식 응답 원문이 공개되는 게 마음에 걸리면** 5-10을 보세요.

진짜 로그인이 필요해지면 Cloudflare Pages + Access 같은 곳으로 옮겨야 합니다.
그때 말씀해 주세요.

### 5-2. 설문 문항 내용이 바뀌었을 때

**파일**: `site/index.html` · **위치**: 180~225번째 줄

| 상수명 | 줄 번호 | 해당 설문 |
|---|---|---|
| `FREE_ITEMS` | 180 | 자유관람 (8문항) |
| `EDUC_ITEMS_STUDENT` | 191 | 교구대여 학생용 (4문항) |
| `EDUC_ITEMS_TEACHER` | 197 | 교구대여 교원용 (4문항) |
| `PROG_ITEMS` | 207 | 학교·가족 (9문항) |
| `CAMP_ITEMS` | 219 | 캠프 (5문항) |

```javascript
const FREE_ITEMS = [
  {label:'프1. 여기를 원하는 문구로 수정', type:'prog'},   // ← 이 부분
  ...
];
```

> `type`은 색상 구분용입니다. `'prog'`는 파란색(프로그램 문항), `'fac'`는 초록색(시설 문항).

문구만 바꾸는 거라면 이 파일 하나만 고치면 됩니다.

### 5-3. 문항 개수가 늘거나 줄었을 때

**두 파일을 함께 고쳐야 합니다.**

#### ① `scripts/fetch-sheets.mjs` — 읽어올 범위와 개수

캠프 문항이 5개 → 6개로 늘었다면 (C~G 에서 C~H 로):

```javascript
  camp: {
    ssId:  '...',
    sheet: '설문지 응답 시트1',
    range: 'A:J',                 // ← I → J 로 넓힌다 (안 넓히면 값이 안 온다)
    map: (row, d) => ({
      year: d.year, month: d.month, day: d.day,
      campType: cell(row, 1),
      scores: toScores(row, 2, 6),  // ← 5 → 6
      comment1: cell(row, 8),       // ← 7 → 8 (한 칸씩 밀림)
      comment2: cell(row, 9),       // ← 8 → 9
    }),
  },
```

> **컬럼 번호는 0부터 시작합니다.**
> A=0, B=1, C=2, D=3, E=4, F=5, G=6, H=7, I=8, J=9, K=10, L=11, M=12, N=13, O=14, P=15
>
> `range`를 안 넓히면 구글이 그 칸을 아예 안 보내줘서 조용히 빈칸이 됩니다. 꼭 같이 고치세요.

### 5-6. 응답자 분류를 바꾸고 싶을 때

설문 보기 항목이 바뀌면 분류 매핑을 수정해야 합니다.
**세 군데 있으니 목적에 맞는 곳을 고르세요.** 전부 `site/index.html` 입니다.

| 함수/상수 | 줄 번호 | 어디에 쓰이나 |
|---|---|---|
| `FREE_PART_ENTRIES` | 230 | 자유관람 상세 탭 |
| `mapProgRespondent()` | 252 | 학교·가족 상세 탭 |
| `classifyPerson()` | 800 | **월말 집계 표 1·2** |

#### 자유관람 (상세 탭)

```javascript
const FREE_PART_ENTRIES = [
  ['학부모 등 보호자','학부모 등 보호자'],
  ['초등학생 학부모','학부모 등 보호자'],
  ...
];
```

- 앞의 값 = 시트에 실제로 들어오는 텍스트
- 뒤의 값 = 통계에 표시할 분류명

> ⚠️ **순서가 중요합니다.** `초등학생 학부모`가 `초등학생`보다 **위에** 있어야 합니다.
> 위에서부터 검사하기 때문에, 짧은 키가 먼저 오면 학부모가 학생으로 집계됩니다.

#### 학교·가족 프로그램 (상세 탭)

```javascript
function mapProgRespondent(v) {
  const s = (v||'').trim();
  if (s.includes('학부모') || s.includes('보호자')) return '학부모 등 보호자';
  if (s.includes('학생')) return '학생';
  if (s.includes('교원') || s.includes('교사') || s.includes('교직원')) return '교원';
  if (s === '') return null;
  return '그외';
}
```

#### 월말 집계 (표 1·2)

`classifyPerson()` — 4번 절의 「사람 분류 규칙」 참고.
새 표현이 들어오면 **여기에도** 조건을 추가해야 보고서 숫자가 맞습니다.

### 5-7. 만족도 응답 표현이 바뀌었을 때

**파일**: `scripts/fetch-sheets.mjs` · **위치**: `scoreToNum()` 함수 (111번째 줄 근처)

현재 인식하는 표현:

| 점수 | 표현 |
|---|---|
| 5 | `매우 만족`, `매우만족`, `매우 그렇다`, `5` |
| 4 | `만족`, `그렇다`, `4` |
| 3 | `보통`, `보통이다`, `3` |
| 2 | `불만족`, `그렇지 않다`, `2` |
| 1 | `매우 불만족`, `매우불만족`, `전혀 그렇지 않다`, `1` |

괄호가 붙은 복합형(`매우 만족(매우 그렇다)`)과
구글 폼 '선형 배율'의 숫자(1~5)도 처리합니다.

새 표현이 생기면 해당 점수 줄에 조건을 추가하세요.

```javascript
if (s.indexOf('아주 좋음') === 0) return 5;   // 예시
```

> ⚠️ **검사 순서를 지키세요.** `'매우 불만족'`을 `'불만족'`보다,
> `'불만족'`을 `'만족'`보다 먼저 검사해야 합니다.
> 순서를 바꾸면 불만족 응답이 만족으로 집계됩니다.

수정 후 확인:


## 6. 문제 해결 (트러블슈팅)

### 가장 먼저 볼 곳 — Actions 로그

저장소 **Actions** 탭 → 마지막 실행 클릭 → **구글 시트 읽기** 단계를 폅니다.

```
  ✅ 자유관람: 412행 · 연도 [2025,2026]
  ✅ 교구대여: 88행 · 연도 [2026]
  ✅ 학교·가족 프로그램: 300행 · 연도 [2025,2026]
  ❌ 여름방학 캠프: 403 The caller does not have permission
```

여기서 대부분 원인이 드러납니다.

---

### 증상: 사이트에 "데이터를 불러오지 못했습니다"

`data.json` 이 아직 안 만들어졌거나 배포가 실패한 겁니다.

1. Actions 탭에서 **데이터 갱신 & 배포** 가 초록 체크인지 확인
2. 빨간 X 면 눌러서 어느 단계에서 멈췄는지 확인
3. 한 번도 안 돌렸다면 **Run workflow** 로 수동 실행

---

### 증상: Actions 로그에 `403 The caller does not have permission`

**시트를 서비스 계정에 공유하지 않은 겁니다.** (2절 ②)

해당 스프레드시트 → 공유 → 서비스 계정 이메일(`…iam.gserviceaccount.com`)을
**뷰어**로 추가하세요.

---

### 증상: Actions 로그에 `구글 토큰 발급 실패`

`GOOGLE_SERVICE_ACCOUNT_JSON` 시크릿이 잘못됐습니다.

- JSON 파일 **내용 전체**를 넣었는지 (앞뒤 중괄호 포함)
- 복사하다 일부가 잘리지 않았는지
- Google Sheets API를 **사용** 으로 켰는지 (2절 ①-3)

시크릿을 다시 등록하고 Run workflow 하세요.

---

### 증상: 특정 탭에만 "해당 월의 응답이 없습니다"

화면이 **그 달 시트에 실제로 들어온 값들을 함께 보여줍니다.**
탭의 `filter` 문자열과 다르면 `TABS` 배열의 `filter` 를 시트 값에 맞추세요.

띄어쓰기 하나만 달라도 안 걸립니다. (`초등학생 SW캠프` vs `초등학생SW캠프`)

---

### 증상: 월말 집계의 특정 행만 비어 있음

| 어떻게 보이나 | 원인 |
|---|---|
| 행 전체가 **회색** | `REPORT_PROGRAMS` 에 `src:null` — 원천이 없는 행 (정상) |
| 숫자가 **0** | 설문은 연결됐는데 그 달 응답이 0건 (정상) |
| 흰 행인데 **빈칸** | `filter` 문자열이 시트 값과 안 맞음 |

---

### 증상: 강사 만족도 칸이 비어 있음

자유관람과 교구대여에는 강사 문항(문항5)이 없습니다. **정상입니다.**
`REPORT_PROGRAMS` 의 `hasInstructor` 로 결정됩니다.

---

### 증상: 숫자가 전부 0으로 나옴

**원인 1**: 컬럼 번호가 틀림 → `SOURCES` 의 `toScores(row, 시작열, 개수)` 확인 (5-3)

**원인 2**: 만족도 표현을 인식 못 함 → `scoreToNum()` 확인 (5-7)

**확인 방법** — 사이트에서 `F12` → Console:

```javascript
DATA.camp.rows.slice(0, 3)
```

`scores` 가 `[null, null, ...]` 이면 표현 인식 실패,
값이 엉뚱한 자리에 있으면 컬럼 번호가 틀린 겁니다.

---

### 증상: 새 응답이 화면에 안 보임

**화면은 실시간이 아닙니다.** 오른쪽 위 "갱신 ○○" 시각을 확인하세요.
그 이후에 들어온 응답은 아직 없습니다.

**Actions → Run workflow** 로 바로 갱신할 수 있습니다 (2~3분 소요).

### 증상: 표가 이상해졌는데 되돌리고 싶음

GitHub 저장소에서 파일 → **History** → 예전 버전 → **Revert** 하거나,
그 버전의 내용을 복사해 덮어쓰면 됩니다.
모든 수정 이력이 남아 있어 언제든 되돌릴 수 있습니다.
